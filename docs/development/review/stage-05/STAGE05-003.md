## 第三次验收的四项失败

| 用例 | 观察 |
| --- | --- |
| 外部目标和 `RUN_GRAPH` 冲突 | 认证 API 同时保存 `RUN_GRAPH` 和要求比较数据源全部记录的文本。查询事件 #10 的范围为 `AUTHORIZED_RUN_GRAPH`，外部覆盖为 `UNKNOWN`。系统写入完成事件 #14，评估状态为 `ANSWERED`，运行以 `OBJECTIVE_REVIEW_COMPLETED` 结束。服务端摘要把结论限定在图内，原始外部目标同时被标记为已回答。[原始轨迹](evidence/attempt-03/EV-345-natural-structured-local-conflicts-with-goal.json) |
| 英文图内目标的同义改写 | 文本要求对当前授权图谱路径排名，系统延后并记录 `GOAL_SCOPE_UNDETERMINED`。[原始轨迹](evidence/attempt-03/EV-343-natural-paraphrased-bounded-ranking.json) |
| 中文图内目标 | “只对当前授权运行图谱中的路径进行排名。”得到相同的延后状态。[原始轨迹](evidence/attempt-03/EV-337-natural-chinese-bounded-ranking.json) |
| 带时点的英文图内目标 | “At tick 0, rank paths within the current authorized run graph.”得到相同的延后状态。[原始轨迹](evidence/attempt-03/EV-348-natural-timed-bounded-ranking.json) |

对照用例包含通过的标准英文图内排名、带结构化范围的图内排名、图内单对象观测，以及外部点查存在性证明。真实证据范围不足时，显式外部目标和对象不匹配的点查被延后。

## 待评审的设计问题

- 当目标原文与冻结范围不一致时，场景校验、运行冻结和最终结果应以哪一层定义为准，系统如何让用户确认这个范围？
- 图内排名的语义边界如何支持中文、同义改写和时点前缀，同时保留对模糊范围的补证状态？
- 运行缓存、工具提交、历史回放和最终研判是否保留足够的证明上下文，使同一个完成状态可以追溯到冻结目标、查询范围和引用事件？
